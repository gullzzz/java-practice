# 多线程系列总结（Thread Summary）

> 本文件是多线程系列（t01 ~ t08）的**最终知识图谱**，串起八章的层层递进关系。
> 状态：t01 ~ t08 全部完成 ✅

---

## 一、为什么是这个顺序（问题链）

八章不是随便排的，而是一条**不断追问的链**——每一章都是被上一章的痛点逼出来的：

```
t01 怎么开一个线程
   │  痛点：线程太贵，来一个任务 new 一个 → OOM
   ▼
t02 线程池：固定几个工人，反复干活
   │  痛点：多个工人抢同一份数据，会算错
   ▼
t03 同步锁：同时只让一个进临界区
   │  痛点：集合这种高频场景，手写锁麻烦又易错
   ▼
t04 并发集合：把锁藏进数据结构里
   │  痛点：线程光互斥不够，还得"你等我我等你"配合
   ▼
t05 线程通信：wait/notify 发信号
   │  痛点：等人/等人齐/等位子这些固定套路，手搓太笨重
   ▼
t06 JUC 工具类：开箱即用的协作积木
   │  痛点：锁只管了"原子性"，还有"可见性、有序性"两个坑没填
   ▼
t07 内存模型：volatile / ThreadLocal / CAS 三路补齐
   │  痛点：Future.get() 干等，任务有依赖/要合并时手搓太乱
   ▼
t08 异步编排：CompletableFuture 声明式流水线
```

**核心规律：每一章的"是什么"，是上一章"怎么办"的答案；它自己又埋下下一章的"为什么"。**

## 三、四条主线 + 一个分水岭

八章分成**四大块**，`t03` 是分水岭：

| 主线 | 章节 | 管的是什么 | 一句话 |
|------|------|-----------|--------|
| **管"线程"本身** | t01、t02 | 线程怎么创建、怎么复用 | 让线程**跑起来、跑得省** |
| **管"线程之间"** | t03 ~ t06 | 互斥、安全容器、通信、协作 | 让线程**一起跑还不乱** |
| **管"内存正确性"** | t07 | 可见性、有序性、无锁原子性 | 让线程**看得见、改得对** |
| **管"任务编排"** | t08 | 异步任务的依赖、合并、兜底 | 让任务**排成流水线不等死** |

> **t03 是那道门：** 跨过它之前，只关心"一个线程怎么跑"；跨过之后，才开始关心"多个线程一起跑会怎样"。

## 四、各章节索引与核心锚点

| 章节 | 目录 | 核心答案 | 关键词 | 面试锚点 |
|------|------|---------|--------|---------|
| t01 | `t01_basics` | 线程怎么开 | `start` vs `run`、生命周期、`yield`/优先级 | `start()` 为什么不能直接调 `run()` |

### 各章"一句话"总结（校准版）

- **t01**：解决"单线程 CPU 利用率低"，教你怎么开线程、认识线程状态。
- **t02**：解决"大量任务下 `new Thread` 会 OOM"，用池化复用固定工人。
- **t03**：解决"多线程并发改共享数据会算错"，靠**互斥**（同一时刻只一个进临界区）——"锁顺序"只是死锁预防的手段，不是主角。
- **t04**：解决"集合高并发场景手写锁太累"，用**封装了锁的现成容器**。
- **t05**：解决"线程间的依赖配合"，核心是**等待 + 唤醒**（条件不满足就 `wait`，满足了被 `notify`），不是简单排先后。
- **t06**：把"**等人 / 等人齐 / 限流**"三类固定协作套路，打包成开箱即用的积木（Latch/Barrier/Semaphore）。
- **t07**：解决"锁只管了原子性、还有两个坑"，用 `volatile`（可见性+有序性）、`ThreadLocal`（线程隔离，压根不共享）、CAS 原子类（无锁原子性）三路补齐。
- **t08**：解决"`Future.get()` 干等"，用 CompletableFuture 把"等结果"升级成"声明式编排流水线"——结果到了自动触发下一步。

## 五、三大特性与工具的对应关系（t07 的核心收获）

| 三大特性 | 是什么 | 谁来救 |
|---------|--------|--------|
| **原子性** | 一个操作不可再分（`i++` 其实是读-改-写三步） | 锁 / CAS |
| **可见性** | 一个线程改了，别的线程立刻能看到 | volatile / 锁 |
| **有序性** | 代码按写的顺序执行（防指令重排） | volatile / 锁 |

> 一句话总纲：**锁管互斥（重），volatile 管可见（轻），ThreadLocal 管隔离（压根不共享），CAS 管无锁原子性（乐观）。**

## 六、同步 vs 异步的思维升级（t08 的核心收获）

| | 同步（t01~t07） | 异步（t08） |
|---|---|---|
| 怎么拿结果 | `get()` 干等 | 声明"算完做什么" |
| 任务有依赖 | 手动 get 再 submit | `thenCompose` 串成一条 |
| 任务要合并 | get 两次再手动加 | `thenCombine` 并行合并 |
| 任务会炸 | try-catch 层层包 | `exceptionally`/`handle` 兜底 |

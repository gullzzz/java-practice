# 阶段 12：枚举（Enum）

配套代码：`src/com/practice/enums/`

---

## 12.1 为什么需要枚举？

用 `int` 常量表示状态有两个致命问题：

```java
// ❌ 常见的反模式
public static final int RED = 0;
public static final int GREEN = 1;
public static final int YELLOW = 2;

int light = RED;
light = 999;  // 编译通过！但这不是合法颜色
```

`int` 枚举是类型不安全的——编译器不会阻止你传入非法值。Java 的 `enum` 在编译期就锁死了所有合法实例。

---

## 12.2 最简单的枚举

```java
public enum TrafficLight {
    RED, GREEN, YELLOW   // 三个常量，仅此而已
}
```

要点：
- `enum` 关键字声明，不是 `class`
- 常量用逗号分隔，最后一个可以加逗号（Java 推荐不加）
- 每个常量本质上是一个 `public static final` 的单例对象
- **enum 不能被 new**，实例数量在编译时就固定了

---

## 12.3 带字段和构造器的枚举

枚举常量可以携带数据：

```java
public enum TrafficLight {
    RED(60), GREEN(45), YELLOW(3);  // ← 调用构造器，常量列表以分号结束

    private final int duration;     // 每个常量持有的数据

    TrafficLight(int duration) {    // 构造器（只能是 private，不用写修饰符）
        this.duration = duration;
    }

    public int getDuration() {
        return duration;
    }
}
```

注意点：
- 常量列表 `RED(60), GREEN(45), YELLOW(3);` 必须在**第一行**
- 如果有字段/方法，常量列表末尾用 **分号** 分隔
- 构造器**默认且强制 private**——你不能在外面 `new TrafficLight(100)`
- 每个常量在类加载时调用一次构造器（线程安全，JVM 保证）

## 12.4 常用方法

| 方法 | 说明 | 示例 |
|------|------|------|
| `values()` | 返回所有常量的数组，按声明顺序 | `TrafficLight.values()` → `[RED, GREEN, YELLOW]` |
| `valueOf(String)` | 按名字查找常量，找不到抛 `IllegalArgumentException` | `TrafficLight.valueOf("RED")` → `TrafficLight.RED` |
| `name()` | 返回常量名 | `TrafficLight.RED.name()` → `"RED"` |
| `ordinal()` | 返回声明位置（从 0 开始） | `TrafficLight.RED.ordinal()` → `0` |

> ⚠️ `ordinal()` 依赖声明顺序，维护时容易出错，大多数场景用自定义字段代替它。

## 12.5 枚举中可以写方法

```java
public enum Operation {
    PLUS {
        public double apply(double a, double b) { return a + b; }
    },
    MINUS {
        public double apply(double a, double b) { return a - b; }
    };

    public abstract double apply(double a, double b);
}
```

这种叫**常量特定的类主体**，每个常量可以覆写枚举的方法。适合每个常量行为不同的场景。

---

## 12.6 枚举实现接口

枚举可以 implements 接口，但不能 extends 类：

```java
public enum TrafficLight implements Describable {
    RED(60) {
        @Override
        public String describe() {
            return "停车！剩余 " + getDuration() + " 秒";
        }
    },
    // ...
}
```

每个常量可以有自己不同的实现，也可以统一在枚举层面实现。

---

## 12.7 枚举 vs 普通类

| | enum | class |
|------|------|-------|
| 实例数量 | 固定，编译期确定 | 不限，运行时 new |
| 继承 | 默认继承 `java.lang.Enum`，不能再继承其他类 | 可以继承任意类 |
| 实现接口 | ✅ 可以 | ✅ 可以 |
| 构造器 | 强制 private | 任意访问修饰符 |
| 序列化 | JVM 内置支持，反序列化不会创建新实例 | 普通序列化机制 |

枚举天生是**单例的最佳实现**——`Effective Java` 推荐用单元素枚举实现单例：

```java
public enum Config {
    INSTANCE;  // JVM 保证只有一个实例，且防反射、防序列化攻击

    private String appName = "MyApp";
    public String getAppName() { return appName; }
}
```

## 面试官视角

| 常见问法 | 得分点 |
|----------|--------|
| "enum 构造器为什么是 private？" | 实例数量固定，外部 new 会破坏这个保证。JLS 规定 enum 构造器不能有 public/protected 修饰符 |
| "enum 和普通 class 有什么区别？" | 继承自 `Enum` 类（不能再继承）、实例固定、构造器私有、values()/valueOf() 自动生成 |
| "enum 能继承其他类吗？能实现接口吗？" | 不能继承（已继承 Enum），但能实现接口 |
| "为什么用 enum 实现单例最好？" | 防反射攻击（构造器抛异常）、防序列化破坏、写法最简洁、线程安全由 JVM 保证 |
| "values() 方法哪来的？" | 编译器自动生成的静态方法，`Enum` 源码里没有 |
| "enum 在 switch 中怎么用？" | switch 原生支持 enum，case 直接写常量名（不带类名），编译器还会检查是否覆盖所有分支 |

---

## 本章小结

1. enum 解决了一组固定常量的类型安全问题
2. 常量可以携带字段、构造器、方法——它就是个特殊的 class
3. `values()` 遍历所有常量，`valueOf()` 按名字查找
4. 枚举天生线程安全、防反射、防序列化破坏，是实现单例的最佳方式

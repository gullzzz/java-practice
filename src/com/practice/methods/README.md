## 3.1 方法的定义

**定义**：方法是封装一段可重用代码的命名代码块，接收零个或多个参数，执行特定逻辑后可返回一个结果（或 void 不返回）。方法是 Java 中最小的功能组织单元。

**解决问题/用途**：写程序最大的敌人是重复代码——同样的逻辑在多处复制粘贴，改一处得改所有。方法将通用逻辑封装一次、随处调用，解决了代码复用和维护一致性的问题。同时命名良好的方法让代码可读性大幅提升——看到 `calculateTotalPrice()` 就知道这段代码在做什么，不用读内部细节。

```java
修饰符 返回类型 方法名(参数类型 参数名, ...) {
    // 方法体
    return 返回值;  // 如果返回类型不是 void
}
```

```java
// 无参数，无返回值
static void greet() {
    System.out.println("Hello!");
}

// 有参数，有返回值
static int add(int a, int b) {
    return a + b;
}
```

- **方法名**：动词开头，驼峰命名（`calculateTotal`）
- **参数**：方法需要的输入，类型必须指定
- **返回值**：`void` 表示没有返回值；`return` 语句结束方法并返回值

## 3.2 参数传递机制

**定义**：Java 中所有参数传递都是**值传递**——基本类型传递的是值的副本，引用类型传递的是引用地址的副本（但副本和原引用指向同一个对象）。

**解决问题/用途**：理解参数传递机制是避免 bug 的关键——很多新手困惑"为什么方法里改了 int 参数外面没变，但改了数组参数外面却变了"。核心理解：基本类型因为是值拷贝所以修改互不影响；引用类型因为是地址拷贝指向同一个对象，通过副本地址操作对象会影响原对象。这决定了你设计方法时是否需要创建防御性拷贝。

**重要！Java 只有值传递**，但引用类型传递的是"引用的副本"：

```java
// 基本类型：传值的副本
void changeValue(int x) {
    x = 999;  // 不影响调用处的变量
}

// 引用类型：传引用的副本（但副本指向同一个对象）
void changeArray(int[] arr) {
    arr[0] = 999;  // 会影响原数组内容！
}
```

图解：
```
基本类型传参：copy 值
  a=10  →  copy of 10 →  x=10 (x改了不影响a)

引用类型传参：copy 引用
  arr → [0x100] → {1,2,3}
        copy of [0x100] → 指向同一个数组 → 修改影响原数组
```

## 3.3 方法重载（Overload）

**定义**：同一个类中允许多个同名方法存在，但参数列表必须不同（个数、类型或顺序不同），编译器根据调用时传入的实参自动选择最匹配的版本。注意返回类型不同不算重载。

**解决问题/用途**：同一个功能对不同类型数据做相似的事，如果方法名不能重复就得取名 `maxInt`、`maxDouble`、`maxLong`——名多难记。重载让你用同一个方法名处理不同类型和数量的参数，使用方只需记住一个名字，编译器帮你选对版本。

**同名方法，参数列表不同** → 编译器根据传参自动选择：

```java
static int max(int a, int b) { ... }
static double max(double a, double b) { ... }
static int max(int a, int b, int c) { ... }
```

重载规则：
1. 方法名相同
2. 参数列表不同（个数、类型、顺序）
3. **返回类型不同不算重载**（编译错误）
4. 与参数名无关

编译器选择"最匹配"的版本。

## 3.4 可变参数（varargs）

**定义**：用 `类型...` 语法声明的方法参数，允许调用时传入零个、一个或多个该类型实参。方法内部将其当作数组处理。一个方法最多一个可变参数，且必须在参数列表最末尾。

**解决问题/用途**：有时你无法预知参数个数——求任意个数的和、拼接任意个字符串、打印任意条日志信息。没有可变参数就只能传数组 `sum(new int[]{1,2,3,4})`，每次要多写 new 和花括号。可变参数让调用方可以 `sum(1, 2, 3, 4)` 直接传值，简洁自然。

```java
static int sum(int... numbers) {
    int total = 0;
    for (int n : numbers) {
        total += n;
    }
    return total;
}

sum(1, 2);        // numbers = {1, 2}
sum(1, 2, 3, 4);  // numbers = {1, 2, 3, 4}
sum();            // numbers = {} (空数组)
```

- `int...` 本质是 `int[]`，但调用更灵活
- 一个方法只能有一个可变参数，且必须在最后

## 3.5 递归

**定义**：方法在自身内部调用自己的编程技法。递归解法通常包含两个关键部分：基准条件（终止递归，不再调用自身）和递归调用（向基准条件靠近）。

**解决问题/用途**：某些问题天然是递归结构的——树遍历（文件目录、DOM 节点）、分治算法（归并排序、快速排序）、数学递推（阶乘、斐波那契）。用循环也能实现，但递归代码往往更贴近问题本质，几行就能表达清楚逻辑。代价是每次递归调用占用栈帧，层次过深会导致 StackOverflowError。

方法调用自身：

```java
static int factorial(int n) {
    if (n <= 1) return 1;       // 基准条件（终止条件）
    return n * factorial(n - 1); // 递归调用
}

factorial(5)
→ 5 * factorial(4)
→ 5 * 4 * factorial(3)
→ 5 * 4 * 3 * factorial(2)
→ 5 * 4 * 3 * 2 * factorial(1)
→ 5 * 4 * 3 * 2 * 1 = 120
```

递归三要素：
1. **基准条件**（终止递归的条件）—— 必须存在！
2. **每次递归向基准条件靠近**
3. **递归调用自身**

注意：递归层次太深会导致 `StackOverflowError`（栈溢出）。

## 3.6 static 方法的含义

**定义**：用 `static` 修饰的方法属于类本身，不属于任何实例。调用时通过 `类名.方法名()`，内部没有 `this` 引用，不能直接访问实例成员。main 方法必须是 static 的，因为程序启动时尚无任何对象。

**解决问题/用途**：有些逻辑不需要依赖对象状态——`Math.max()` 不需要任何实例数据，只是数学计算。静态方法提供了一种组织工具函数的方式，不需要先 new 一个对象就能用。也常用来实现工厂方法（`Calendar.getInstance()`）、单例模式等设计模式。

```java
static int add(int a, int b) { ... }
```

- 属于**类本身**，不属于任何实例
- 调用方式：`ClassName.method()` 或同类中直接 `method()`
- 没有 `this` 引用
- main 方法必须是 static（程序启动时还没有任何对象）

## 3.7 方法设计原则

1. **单一职责**：一个方法只做一件事
2. **命名清晰**：方法名应准确描述其功能
3. **参数不宜过多**：超过 3-4 个考虑封装为对象
4. **短方法**：一般不超过 20-30 行
5. **无副作用更好**：优先写不修改外部状态的方法

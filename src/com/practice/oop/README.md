## 5.1 面向对象核心概念

**定义**：面向对象编程（OOP）是一种以"对象"为中心的编程范式。类是对象的模板/蓝图，定义了对象有哪些属性（数据）和方法（行为）。对象是类的具体实例。四大核心概念——类、对象、属性、方法——构成了 OOP 的基本词汇。

**解决问题/用途**：传统面向过程编程以函数为中心，数据和行为分离，随着系统变大，数据和操作散落各处难以维护。OOP 将数据和行为绑定在一起（封装），让代码结构更贴近人类对世界的认知（"狗"这个概念有名字属性和叫的行为），降低大型软件的复杂度。

| 概念 | 含义 |
|------|------|
| **类（Class）** | 对象的蓝图/模板 |
| **对象（Object）** | 类的具体实例 |
| **属性（Field）** | 对象的状态/数据 |
| **方法（Method）** | 对象的行为/功能 |

类比：`Person` 类是"人类"这个概念，`new Person("张三", 25)` 是具体的一个"人"。

## 5.2 类的定义

**定义**：类使用 `class` 关键字定义，包含字段（属性）、构造器（初始化对象的方法）和方法（行为）三个主要组成部分。一个 `.java` 文件通常定义一个类，类名与文件名必须一致。

**解决问题/用途**：类提供了一种自定义数据类型的能力——Java 内置了 int、String，但没有 Person、Order、Product 这些业务概念。通过定义类，你可以创建出匹配业务领域的自定义类型，让代码表达力更强。

```java
public class Person {
    // 1. 字段（属性）
    private String name;
    private int age;

    // 2. 构造器
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // 3. 方法
    public void introduce() {
        System.out.println("我叫" + name);
    }
}
```

## 5.3 构造器（Constructor）

**定义**：构造器是一种特殊的方法，名称必须与类名相同，没有返回类型（连 void 也没有）。通过 `new` 关键字调用，负责初始化新创建的对象。如果没有写任何构造器，编译器会自动生成一个无参构造器；一旦写了任意构造器，编译器就不再自动生成。

**解决问题/用途**：对象创建时通常需要初始化数据——一个 Person 诞生时就应该有名字和年龄。构造器强制性地在对象创建瞬间完成必要的初始化，确保对象一诞生就处于有效状态，避免"半成品"对象被使用。

```java
// 无参构造器
public Person() {
    this("未命名", 0);  // 调用另一个构造器
}

// 全参构造器
public Person(String name, int age) {
    this.name = name;
    this.age = age;
}
```

要点：
- 构造器名称**必须与类名相同**
- **没有返回类型**（连 void 都没有）
- 用 `new` 调用：`Person p = new Person("张三", 25);`
- 如果没有写任何构造器，编译器会**自动生成一个无参构造器**
- 如果写了任意构造器，编译器**不再自动生成**无参构造器
- `this(...)` 调用另一个构造器，**必须放在第一行**

## 5.4 封装（Encapsulation）

**定义**：封装是将对象内部状态（字段）隐藏为 private，通过 public 的 getter/setter 方法提供受控的访问通道。核心思想是"隐藏内部实现，只暴露安全的接口"。

**解决问题/用途**：如果字段 public，任何代码都能任意修改——`person.age = -999` 这种无效值就能进来。封装让你在 setter 中加校验逻辑拦截非法值，且未来可以随意修改内部实现（如 age 从 int 改为 LocalDate 计算得出）而不影响所有调用方。这是构建健壮可维护系统的基石。

**核心思想**：隐藏内部实现，只暴露安全的接口。

```java
public class Person {
    private String name;     // 字段私有

    public String getName() {      // Getter（访问器）
        return name;
    }

    public void setName(String name) {  // Setter（修改器）
        if (name != null && !name.isBlank()) {  // 校验
            this.name = name;
        }
    }
}
```

访问修饰符：

| 修饰符 | 同类 | 同包 | 子类 | 任何地方 |
|--------|------|------|------|----------|
| `private` | ✓ | | | |
| `default`（不加） | ✓ | ✓ | | |
| `protected` | ✓ | ✓ | ✓ | |
| `public` | ✓ | ✓ | ✓ | ✓ |

最严格的 `private` 到最开放的 `public`。封装原则：**字段用 private，方法根据需要开放**。

#### private — 仅限本类内部

**定义**：最严格的访问级别，只有定义它的类本身可以访问。同一个文件里的其他类、同包子类、外部调用方，统统不可见。

**什么时候用**：字段几乎一律用 private（封装的核心），内部的辅助方法（只在本类使用的 helper 方法）也用 private。原则：能藏起来就别给人看。

#### default（包级私有）— 不加任何修饰符

**定义**：不写任何访问修饰符时的默认级别。同一个包内的类可以访问，不同包的类（即使子类）访问不了。没有对应的关键字，就是"不写"。

**什么时候用**：同一个包内密切协作的类之间共享的内部方法或数据。比如在一个 library 包下，几个类需要互相调用一些"对外不暴露但对内可见"的方法。

#### protected — 对子类开放

**定义**：同包内可见 + 不同包的子类可见。专门为继承场景设计——父类的某些成员需要被子类使用，但不希望随便谁都能直接调用。

**什么时候用**：模板方法模式（父类定义骨架，子类实现细节）中的钩子方法；给子类提供可重写的辅助方法；框架设计中让子类能访问父类的一些内部状态。

#### public — 对所有人开放

**定义**：没有任何限制，任何地方的任何类都能访问。属于类的"公开 API/接口"。

**什么时候用**：对外暴露的构造器、公共方法（如 getter/setter）、常量。对外暴露的 public 方法要谨慎设计——一但发布，修改可能会破坏所有调用方。

## 5.5 this 关键字

**定义**：`this` 是方法内部的一个隐式引用变量，指向调用当前方法的对象本身。可以用来区分同名的字段和参数、调用本类的其他构造器、在链式调用中返回当前对象。

**解决问题/用途**：当方法参数和字段同名时（构造器中很常见），没有 `this` 就无法区分"哪个是参数哪个是字段"。另外 `this()` 让一个构造器可以复用另一个构造器的初始化逻辑，避免代码重复。

`this` 指向**当前对象**本身：

```java
public Person(String name, int age) {
    this.name = name;  // this.name 是字段，name 是参数
    this.age = age;
}
```

用途：
1. **区分字段和参数**（同名时）
2. **this() 调用本类其他构造器**
3. **返回当前对象**（链式调用）：`return this;`

## 5.6 static（静态）vs 实例

**定义**：static 成员（字段/方法）属于类本身，在类加载时初始化，全局只有一份，所有实例共享。实例成员属于每个对象，每创建一个对象就有一份独立副本。静态方法中不能使用 this，不能直接访问实例成员。

**解决问题/用途**：某些数据是所有对象共享的——比如总共创建过多少个 Person 对象（计数）、数据库连接池、全局配置——用 static 字段实现，一处修改所有可见。静态方法则提供不依赖对象状态的工具函数，调用方无需先创建对象。

| | 实例成员 | 静态成员 |
|------|----------|----------|
| 归属 | 属于**对象** | 属于**类** |
| 访问方式 | `obj.method()` | `ClassName.method()` |
| 内存 | 每个对象一份 | 整个类一份（共享） |
| 有 `this` | 有 | 没有 |
| 访问范围 | 可访问静态和实例 | 只能直接访问静态 |

```java
public class Person {
    private static int totalCount = 0;  // 类变量（所有实例共享）

    public Person() {
        totalCount++;  // 每创建一个对象+1
    }

    public static int getTotalCount() {  // 类方法
        return totalCount;
    }
}

// 调用
int count = Person.getTotalCount();  // 通过类名调用
```

## 5.7 toString() 与 equals()

**定义**：`toString()` 和 `equals()` 是定义在 Object 类中的方法，所有 Java 类都会继承。`toString()` 返回对象的字符串表示，默认是 `类名@哈希码`。`equals()` 判断两个对象是否"相等"，默认使用 `==` 比较地址。实际项目中通常需要重写这两个方法。

**解决问题/用途**：调试时直接 `System.out.println(obj)` 看到的是无意义的 `Person@3cd1a2f1`——重写 toString() 后能看到 `Person{name='张三', age=25}`。equals() 同样如此：默认的地址比较意味着"内容相同但不同时刻创建的两个对象"被视为不同，重写 equals() 改为按业务字段比较才能实现"内容相等即相等"。

这两个方法定义在 `Object` 类（所有类的祖先）中，通常需要**重写**：

```java
@Override
public String toString() {
    return "Person{name='" + name + "', age=" + age + "}";
}

@Override
public boolean equals(Object obj) {
    if (this == obj) return true;
    if (obj == null || getClass() != obj.getClass()) return false;
    Person other = (Person) obj;
    return age == other.age && name.equals(other.name);
}
```

- `toString()`：`System.out.println(obj)` 时自动调用
- `equals()`：默认 `==` 比较地址，需要按内容比较时必须重写
- `hashCode()`：如果重写 `equals`，必须同时重写 `hashCode`（集合中会用到）

## 5.8 对象创建过程

**定义**：`new Person("张三", 25)` 的执行分为四步——堆中分配内存、字段初始化为默认值（0/null/false）、执行构造器中的实际赋值、将堆中对象的地址赋值给栈上的引用变量。

**解决问题/用途**：理解对象创建过程有助于掌握顺序依赖——构造器执行时字段已经分配了默认值，这意味着即便构造器中途出异常，也能看到默认值而非随机内存值。也解释了为什么默认值在构造器之前已经存在。

```
Person p = new Person("张三", 25);

1. 堆中分配内存
2. 字段初始化为默认值（name=null, age=0）
3. 执行构造器中的赋值（name="张三", age=25）
4. 将对象的地址赋给引用变量 p
```

## 5.9 内存分析

**定义**：从内存角度来看，`Person p = new Person()` 中，引用变量 `p` 存储在栈上（只占4/8字节存地址），`new Person()` 创建的实际对象存储在堆上（占较大空间）。p 的值就是堆中对象的起始地址。

**解决问题/用途**：这个内存模型解释了很多日常现象——为什么 `=` 赋值引用类型只是复制了地址（两个变量指向同一对象），为什么要用 `equals()` 比较内容而不是 `==`（后者比较的是栈中存储的地址值），为什么方法参数传递中改引用对象的内部会影响调用方。

```
栈                    堆
┌─────────┐     ┌──────────────────┐
│ p ──────┼──→  │ Person对象        │
│ (四个字  │     │ name = "张三"    │
│  节的引  │     │ age = 25        │
│  用)     │     └──────────────────┘
└─────────┘
```
